# {{name}} — commonplace schema

You maintain this commonplace: a folder of plain markdown that is the durable memory
for research, projects and the person it belongs to. The user curates sources
and asks questions; you read, write, link, cite and keep it tidy. These rules
keep the commonplace consistent across sessions, agents and models. Where a rule is
missing, ask, then propose one for "Local rules" at the bottom.

**Purpose:** {{purpose}}

The `commonplace` command line tool does the bookkeeping (hashing, links, citation
checks, index, search). Run `commonplace doctor` to confirm it works here. If it does
not, follow the same rules by hand and say so in your report.

## 1. Layout

```
AGENTS.md            this schema (CLAUDE.md just imports it)
commonplace.toml           tool config: packs, lint thresholds, retired terms
TAGS.md              tag registry; only listed tags may be used
index.md             GENERATED by `commonplace index`: orientation + catalogue (L1)
overview.md          the big picture, written by you, kept current
log.md               append-only operation log (rotated by the tool)
error-book.md        recurring mistakes turned into standing constraints
open-questions.md    what is unresolved, with what would resolve it
inbox/               raw captures, unprocessed drops (CODE: capture)
journal/             YYYY-MM-DD.md daily notes: what happened, decided, learned
sources/raw/         IMMUTABLE originals. Never edit, rename or delete.
sources/text/        faithful markdown of each original, with page/section anchors. Never edit.
sources/notes/       one note per source: TL;DR, summary, key quotes (L1–L3)
projects/<slug>/     outcome-bound work with an end (PARA: Project)
areas/<slug>/        ongoing responsibilities with a standard (PARA: Area)
resources/           reusable knowledge (PARA: Resource)
  concepts/          one idea per page, claim-style title, densely linked
  entities/          specific named things: organisations, products, tools, cases
  topics/            maps of content: orientation + generated page lists
  syntheses/         saved answers, comparisons, analyses
  playbooks/         procedures you have learned: how to do X here
memory/              about the user: Profile, Preferences, Glossary, people/, decisions/
questions/           open questions as pages (type: question)
reviews/             persona review packets and findings
archive/             inactive projects/areas; excluded from search by default
indexes/             GENERATED hubs when a group outgrows index.md
.commonplace/              tool-owned: manifest (hashes), templates, packs
```

Sources are global: one source may serve many projects, so sources never live
inside a project folder. Projects link to sources; sources list `projects`.

## 2. Page types

| type | lives in | one line |
|---|---|---|
| source | sources/notes/ | summary ladder for exactly one original |
| concept | resources/concepts/ | one idea or claim; title states it |
| entity | resources/entities/ | one named thing (`kind`: organization, product, tool, case, place, event, work, other) |
| topic | resources/topics/ | map of content for a subject (`scope`: folder or tag) |
| synthesis | resources/syntheses/ | an answer worth keeping (`question`) |
| playbook | resources/playbooks/ | a procedure that worked, with preconditions and checks |
| project | projects/<slug>/ | outcome, due date, status, next actions |
| area | areas/<slug>/ | standard to maintain, review cadence |
| decision | memory/decisions/ or a project | ADR: context, options, decision, consequences |
| person | memory/people/ | someone in the user's life or work |
| journal | journal/ | one day |
| capture | inbox/ | fleeting; processed within days then deleted or filed |
| question | questions/ | open question, what would resolve it |
| review | reviews/ | persona findings |

Packs add types (see §9). Create a page with `commonplace new <type> "<Title>"`, which
applies the template and checks the title is unique. Create a concept or entity
page only when it matters in two or more sources or is central to one.
Otherwise mention it in prose. Stub sprawl is the default failure.

Before creating any page: `commonplace search "<name>"` and check aliases. If it
exists, extend it. Never write a `[[link]]` to a page you have not confirmed
exists (`commonplace links check` catches it, but do not rely on that).

## 3. Naming

- Synthesis pages: `Title Case.md`, singular, the most common full name or a
  claim-style sentence for concepts ("Fabricated citations breach the duty not
  to mislead the court"). Other names go in `aliases`.
- Sources: `YYYY-MM-DD Short Title` (publication date; ingest date if unknown).
  The tool assigns this at `commonplace ingest`.
- Projects and areas: folder `projects/<kebab-slug>/`, page `<Title>.md` inside.
- Journal: `YYYY-MM-DD.md`. Reviews: `YYYY-MM-DD <persona> <scope>.md`.
- Avoid `# ^ [ ] | / \ :` in titles. Renames go through `commonplace rename`.

## 4. Frontmatter

Every page starts with YAML frontmatter. Required everywhere: `type`.
Required on synthesis pages (concept, entity, synthesis, playbook, decision and
cited pack types): `tags`, `status`, `confidence`, `description`, `created`,
`updated`, `sources`.

- `description`: one line, claim-style. It becomes the index entry (L0), so
  write it for someone deciding whether to open the page.
- `status`: `seed` (thin) · `growing` · `mature` · `superseded`. Projects use
  `active|paused|done|archived`; areas `active|dormant|archived`; sources
  `registered|converted|summarised|integrated|superseded`.
- `confidence`: `high` · `medium` · `low` · `contested`. Justify anything
  other than high in one line in the body.
- `sources`: list of source notes, quoted: `["[[2025-01-08 Mavundla v MEC]]"]`.
- `aliases`, `tags`: lists. `related`, `up`: links to related pages / parent map.
- `confidentiality`: `public` · `personal` · `confidential` · `privileged`.
  Default personal. A page may not quote a source more confidential than itself.
- `superseded_by`: link, when status is superseded. Never delete knowledge.
- `contradictions`: list of `{with: "[[Page]]", severity: soft|scope|hard,
  status: open|resolved, note: "..."}`.
- `reviews`: appended by `commonplace review record`.
- Single-valued facts are properties, not tags.

## 5. Tags

Only tags in `TAGS.md` (Active) may be used. Lowercase kebab, one namespace:
`topic/<name>` for subjects (at most 5 per page), `todo/<flag>` for work flags.
Need a new tag? Add it under Proposed in TAGS.md with a reason and the pages
that would use it; apply it only after the user approves.

## 6. Page body

1. `# Title`
2. For synthesis pages: a 2–4 sentence summary, then the substance in sections,
   then `## Related` with 3–8 links each with a few words on the relationship.
3. Every factual sentence that comes from a source carries a citation footnote.
   Claims you cannot source are prefixed `unsourced:` and the page's confidence
   drops to low until a source is found.
4. Write in your own words. Quote only verbatim, only inside citations, 3–80 words.
5. Never silently overwrite a claim. When sources disagree, keep both with
   citations, add a `contradictions` entry and set confidence to `contested`.
6. When something changes, update the reference sections, not just a changelog
   line. A page that says "currently" must be dated by its `updated` field.

## 7. Citations

Syntax: a markdown footnote whose definition starts with the source link, then
a locator, then the verbatim quote in double quotes:

```
Counsel must verify every authority an AI tool produces.[^1]

[^1]: [[2025-01-08 Mavundla v MEC]] para 26 "counsel lazily omitted to verify the research"
```

- Locators: `p.12`, `pp.12-14` (page markers in the text layer), `para 26` or
  `[26]` (numbered paragraphs, as in judgments), `§3.2` (section heading),
  `L120-128` (lines of the text layer), `00:14:32` (media; unverifiable span).
- The quote must appear verbatim inside the cited span of `sources/text/`.
  `commonplace cite verify` checks it deterministically; `commonplace cite find "<quote>"`
  gives you the right locator. Fix a failing citation by re-reading the source,
  never by adjusting the quote to what you remember.
- Cite sources, not wiki pages. Wiki pages link; sources are evidence.
- A verified quote proves existence, not support. The Citation Auditor persona
  judges whether the quote supports the sentence.

## 8. Operations

### Ingest ("ingest this", files dropped in inbox/)
1. `commonplace ingest <file> --title "..." --date YYYY-MM-DD --origin <url|where>` (never copy files into sources/ by hand).
2. Read the conversion report. If the text layer is missing or low fidelity,
   convert it yourself (PDF: keep page markers `<!-- page:N -->`; long documents
   may be split into `sources/text/<id>/NN Section.md` with `section` and
   `page_from` frontmatter) and run `commonplace source attach-text "<id>"`.
3. Spot-check the text layer against the original (first page, one table, last page).
4. Discuss 3–5 takeaways with the user unless in batch mode.
5. Write the source note: TL;DR (≤50 words), Summary (≤300 words), Key quotes
   (verbatim, with locators), Relevance and open questions. Set `status: summarised`.
6. Integrate: update or create concept, entity, project pages (search first;
   extend, don't create). Record contradictions. Set `status: integrated`.
7. `commonplace cite verify --changed` → `commonplace index` → `commonplace lint --changed` → fix
   every error → `commonplace log add ingest "<title>" --note "Created: ..." --note "Updated: ..."`.

### Query (any question the commonplace might answer)
1. Read `index.md`, then the relevant topic or project page, then `commonplace search`.
2. Read source notes first; open `sources/text/` spans for anything you will quote.
   For "how does X relate to Y", `commonplace graph related "<page>"` and
   `commonplace graph path "<A>" "<B>"` give neighbours and chains with reasons.
3. Answer with citations. If the answer required synthesis, offer to file it in
   `resources/syntheses/` so the next query starts further ahead.
4. Say clearly when the commonplace cannot answer and you are answering from general
   knowledge (`unsourced:`).

### Research ("research X", "find out", "compare")
Write `projects/<slug>/Research Plan.md` first: question tree, sources you
expect, stopping rule, effort budget (simple: do it yourself; comparison: 2–4
subagents; broad: more). Subagents save originals and write source notes, and
return paths plus a short summary, not full text. Then synthesise, find the
thinnest claim and do one targeted pass on it, run `cite verify`, run the
Citation Auditor and Skeptic personas, then produce the deliverable.

### Lint ("clean up", "health check", after any writing session)
`commonplace lint --changed` then fix, then `commonplace lint` weekly. Weekly also run
`commonplace graph gaps` (wanted pages, orphans, clusters without a map page, thin
evidence, bridges), `commonplace graph suggest-links` (unlinked mentions) and
`commonplace graph conflicts` (pairs to compare); the tool nominates, you judge.
It cannot judge semantics: also look for stale claims a newer source
supersedes, pages to merge or split (`commonplace dedupe`), and gaps worth a
search. Recurring mistakes go into `error-book.md` as constraints.

### Review (before a deliverable leaves the commonplace)
`commonplace review prepare <persona> <pages>` builds a packet. Give it to a
fresh-context subagent (a different model when possible). Record the JSON
findings with `commonplace review record`. Resolve each finding: fix, waive with a
reason, or file an open question.

### Distill and reflect (weekly, or when asked)
Process inbox/ and recent journal pages into memory/, projects and concepts.
Promote repeated procedures into playbooks. Check active projects have a next
action; park or archive the rest (`commonplace archive`). Update `overview.md`.

## 9. Packs

`commonplace.toml` lists enabled packs (`ea`, `legal`, `compare`, `study`) and,
for the legal pack, the `jurisdiction` profile (`za`, `au`, `en`, or one added
under `.commonplace/packs/legal/jurisdictions/`). A
pack adds page types, templates, lint rules and traces under
`.commonplace/packs/<name>/pack.yaml`, and its workflow, personas and reference live
in the skill's `packs/<name>/` folder. Pack lint rules are mandatory. Read the
pack workflow before working in its domain.

## 10. Memory about the user

`memory/Profile.md`, `Preferences.md`, `Glossary.md`, `people/` and
`decisions/` hold standing facts. Update them when you learn something durable
(a preference, a role, a relationship, a decision), dated, and ask before
storing anything sensitive (health, finances, legal matters of others). Prefer
superseding a fact with a date over deleting it.

## 11. Never

- Never modify, rename or delete anything in `sources/raw/` or `sources/text/`.
- Never invent a citation, a locator or a link target. Never adjust a quote to fit.
- Never delete a page or a claim; supersede it or propose deletion and wait.
- Never rename many pages, move folders or change this schema's standard
  sections without asking. Local additions go under "Local rules".
- Never store credentials. Never quote privileged material into a less
  confidential page or export.
- Never name the model or tool that wrote a page in pages, logs or commits.

## 12. Finish every session

`commonplace cite verify --changed` → `commonplace index` → `commonplace lint --changed` → fix
errors → `commonplace log add <op> "<what and why>"` → `git commit` if this is a
repository. Then report: pages created and updated, unresolved contradictions,
unverified items, open questions, lint status.
